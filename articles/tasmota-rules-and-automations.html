Tasmota Rules and Automations: Programming Smart Devices Without Code

📅 July 6, 2026 ⏱️ 14 min read ✍️ 3D Print Starter Team
⚙️

Once you've flashed Tasmota firmware onto your Sonoff devices, you unlock one of the most powerful features in the DIY smart home world: the Tasmota rules engine. This built-in rule system lets you program complex automations directly on your device — no Home Assistant, no Node-RED, no coding skills required.

In this guide, you'll learn how Tasmota rules work, the syntax you need to know, and real-world automation examples you can implement today. Whether you want auto-off timers, conditional logic, or sensor-triggered actions, Tasmota rules handle it all locally.

What Are Tasmota Rules?

Tasmota rules are if-this-then-that (IFTTT) statements that run directly on your ESP8266 or ESP32 device. They're stored in the device's memory and execute without needing an external automation platform.

Unlike cloud-based automations that depend on internet connectivity, Tasmota rules:

  • Run locally — no internet required
  • Execute instantly — no cloud latency
  • Survive reboots — rules persist in flash memory
  • Use minimal resources — efficient enough for the ESP8266

Think of the rules engine as a tiny automation brain built into every Tasmota device. Once configured, your Sonoff can make decisions on its own based on sensor inputs, time, power state, or external triggers.

Understanding Tasmota Rule Syntax

Tasmota rules use a straightforward syntax that might look intimidating at first, but becomes intuitive once you understand the structure:

Rule1 ON [trigger] DO [action] ENDON

Let's break down each component:

  • Rule1 — Rules are numbered 1-5, each with independent enable/disable states
  • ON [trigger] — The condition that activates the rule (sensor reading, button press, time, etc.)
  • DO [action] — What the device should do when triggered
  • ENDON — Marks the end of the rule block

You can chain multiple triggers and actions using AND, OR, and the Backlog command to execute sequences.

Key Triggers

Here are the most common triggers you'll use:

Trigger Description Example
Power1#State=1 Relay 1 turns ON When living room light turns on
Switch1#State=1 External switch pressed When physical button is pressed
Analog#A0=512 Analog sensor threshold When light sensor reads specific value
Time#Minute=30 Every 30 minutes Scheduled actions
Sensor#DHT11~Temperature>25 Temperature exceeds threshold Turn on fan when hot
Var1=1 Variable equals value Programmable flag/trigger

Key Actions

Common actions you can trigger:

  • Power1 ON/OFF/TOGGLE — Control relays
  • Delay X — Wait X seconds before next action
  • Backlog — Execute multiple commands in sequence
  • Publish — Send MQTT message
  • RuleTimer — Set countdown timer
  • Power ON — Turn on without specifying relay number

Getting Started: Enable Rules in Tasmota

Before you can use rules, you need to enable the rules system in Tasmota:

  1. Open your Tasmota device's web interface (find its IP address)
  2. Go to Configuration → Configure Other
  3. Find the Rules option and set it to Enabled
  4. Click Save
  5. Navigate to Console in the top menu

The console is where you'll type your rules commands. You'll see real-time status messages and feedback as you test.

Rule Management Commands

Use these commands in the Tasmota console:

Rule1 ON ... DO ... ENDON     // Define the rule
Rule1 1                         // Enable Rule1
Rule1 0                         // Disable Rule1
Rule1                           // Show current Rule1 definition
Rule1 4                         // Enable Rule1 after boot (persistent)
Backlog                         // Combine multiple commands

For multiple rules, use Rule2, Rule3, etc. Each rule can be independently enabled, disabled, or configured to start on boot.

10 Practical Tasmota Automation Examples

Let's dive into real-world automations you can implement right now. Each example includes the complete rule command — just copy, paste, and adapt to your setup.

1. Auto-Off Timer: Turn Off Light After 30 Minutes

The most common automation — automatically turn off a light after you've left the room:

Rule1 ON Power1#State=1 DO Backlog Delay 1800; Power1 0 ENDON

How it works: When the relay turns on, the rule starts a 1800-second (30-minute) delay. After the delay, it sends the Power1 0 command to turn off the relay. Perfect for bathrooms, closets, or garages.

Customization: Change 1800 to your preferred delay in seconds (600 = 10 minutes, 3600 = 1 hour).

2. Toggle Button: Single Press On/Off

Convert a Sonoff Basic into a simple toggle switch:

Rule1 ON Switch1#State=1 DO Power1 TOGGLE ENDON

How it works: Every time the external switch is pressed, the relay toggles between on and off. This is ideal for replacing traditional wall switches with Sonoff modules.

3. Motion-Triggered Light

Connect a PIR motion sensor to your Sonoff and automate lighting:

Rule1 ON Switch1#State=1 DO Power1 ON; RuleTimer1 60 ENDON
Rule1 ON Rules#Timer=1 DO Power1 OFF ENDON

How it works: When motion is detected (Switch1 goes HIGH), the light turns on and a 60-second timer starts. If no more motion is detected, the timer expires and the light turns off.

4. Sunrise/Sunset Based Lighting

Control lights based on time of day:

Rule1 ON Time#Initialized DO var1 %sunrise% ENDON
Rule1 ON Time#Minute=30 DO IF (var1 %time%) == 1 AND (var2==0) == 1 THEN Power1 ON; var2 1 ENDIF ENDON

Simpler approach using Time#Hour:

Rule1 ON Time#Hour=18 DO Power1 ON ENDON     // Turn on at 6 PM
Rule1 ON Time#Hour=23 DO Power1 OFF ENDON    // Turn off at 11 PM

How it works: This is a basic time-based rule. For more sophisticated sun-based triggers, consider using Home Assistant which has built-in sun entities.

5. Temperature-Triggered Fan

Turn on a fan when temperature exceeds a threshold:

Rule1 ON AM2301#Temperature>28 DO Power2 ON ENDON
Rule1 ON AM2301#Temperature<26 DO Power2 OFF ENDON

How it works: When the DHT22 sensor reads above 28°C, the fan (connected to relay 2) turns on. It turns off again when temperature drops below 26°C (hysteresis prevents rapid on/off cycling). This is excellent for greenhouse automation or server rooms.

6. Power State Recovery After Outage

Configure the device to restore its last state after a power failure:

SetOption65 1

How it works: This SetOption command enables power state recovery. When power is restored, the device returns to the state it was in before the outage. Essential for critical automation scenarios like aquarium equipment or sump pumps.

7. Double-Tap for Special Action

Program different actions for single vs. double button presses:

Rule1 ON Button1#State=3 DO Power1 TOGGLE ENDON          // Single press
Rule1 ON Button1#State=4 DO Power2 TOGGLE; RuleTimer1 300 ENDON  // Double press (3 = single, 4 = double)

How it works: Single press toggles relay 1. Double press within 1 second toggles relay 2 and starts a 5-minute auto-off timer. Perfect for bed-side implementations where you want different behaviors for different press patterns.

8. Humidity-Triggered Dehumidifier

Similar to temperature, but for humidity control:

Rule1 ON AM2301#Humidity>70 DO Power1 ON ENDON
Rule1 ON AM2301#Humidity<60 DO Power1 OFF ENDON

How it works: When humidity exceeds 70%, the dehumidifier turns on. It shuts off when humidity drops below 60%. This is perfect for bathrooms, basements, or indoor plant monitoring setups.

9. MQTT-Triggered Automation

Trigger actions based on MQTT messages from another system:

Rule1 ON MQTT#Connected DO Backlog Publish stat/tasmota/RESULT {"Event":"Ready"} ENDON

How it works: When the device connects to MQTT, it publishes a "Ready" event. You can then subscribe to this topic in Home Assistant or Node-RED to trigger further automations across your system.

10. Pulse Mode: Run Device for X Seconds

Activate a device for a specific duration (great for sprinklers, door strikes, etc.):

Rule1 ON Switch1#State=1 DO Backlog Power1 ON; RuleTimer1 300; ENDON
Rule1 ON Rules#Timer=1 DO Power1 OFF ENDON

How it works: When triggered, the device turns on for exactly 300 seconds (5 minutes) then automatically turns off. Change 300 to control duration. Perfect for smart door lock strikes or irrigation systems.

Advanced Rule Techniques

Using Variables (Var1-9)

Tasmota variables let you store and compare values across rule executions:

Var1 0                           // Initialize Var1 to 0
Rule1 ON Power1#State=1 DO Var1 1 ENDON    // Set Var1 when relay turns on
Rule1 ON Power1#State=0 DO Var1 0 ENDON    // Reset Var1 when relay turns off
Rule1 ON Var1=1 DO Power2 ON ENDON         // If Var1 is 1, turn on relay 2

Multi-Condition Logic

Combine multiple triggers with AND/OR logic:

Rule1 ON (Switch1#State=1 AND Var1=1) DO Power1 ON ENDON
Rule1 ON (Switch1#State=1 OR Switch2#State=1) DO Power1 ON ENDON

Sequential Commands with Backlog

Execute multiple actions in sequence:

Rule1 ON Switch1#State=1 DO Backlog Power1 ON; Power2 ON; Publish cmnd/otherdevice/POWER ON; ENDON

How it works: When triggered, the device: turns on relay 1, turns on relay 2, and sends an MQTT command to another device — all in sequence with minimal delay between commands.

Debugging Your Rules

When rules don't work as expected, here's your debugging workflow:

  1. Check rule status: Type Rule1 in console to see the current rule definition
  2. Verify rule is enabled: Rules show ON or OFF status
  3. Enable rule logging: Use RuleDebug 1 to see rule trigger events in console
  4. Test the trigger manually: Send the trigger condition via console and watch for response
  5. Simplify and test: Strip down complex rules to isolate the problem

Rules vs. Home Assistant Automations: When to Use Each

Now you might be wondering: should I use Tasmota rules or Home Assistant automations? Here's the breakdown:

Use Case Tasmota Rules Home Assistant
Single device logic ✅ Perfect Overkill
Instant response (< 100ms) ✅ Best Network latency
Multi-device coordination ⚠️ Possible but complex ✅ Much easier
Sensor fusion / complex logic ⚠️ Limited ✅ Full power
Works without network ✅ Always ❌ Needs HA running
Easy visualization ❌ Console only ✅ Dashboard UI

My recommendation: Use Tasmota rules for device-local logic (timers, simple triggers, failsafes) and Home Assistant for complex, multi-device automations. This hybrid approach gives you the best of both worlds.

Comparison: Tasmota Rules vs. ESPHome Automations

If you're deciding between Tasmota and ESPHome for your smart home projects, here's how their automation systems compare:

  • Tasmota rules: Text-based, device-local, minimal resources, perfect for simple to moderate logic
  • ESPHome automations: YAML-based, compile-time optimized, tighter Home Assistant integration

For most users, Tasmota rules are easier to get started with and sufficient for common automations. If you need complex sensor fusion, custom C++ logic, or extremely tight HA integration, ESPHome offers more power at the cost of higher complexity.

Performance Tips

  • Limit rule complexity: Each rule check consumes CPU cycles. Keep rules simple.
  • Use RuleTimers efficiently: One timer per rule, reuse by resetting.
  • Disable unused rules: If a rule isn't needed, disable it with Rule1 0.
  • Test in isolation: Enable one rule at a time to identify conflicts.

Final Thoughts

Tasmota rules transform your Sonoff devices from simple smart switches into intelligent automation controllers. Whether you're implementing auto-off timers, sensor-triggered actions, or conditional logic, the rules engine handles it all locally without cloud dependencies.

The best part: these rules persist across reboots and work even when your network is down. Start with one simple rule, test it thoroughly, then expand your automation library over time.

Have a cool Tasmota rule you'd like to share? The Tasmota community forums and r/homeassistant on Reddit are great places to find inspiration and troubleshoot issues.

Ready to take your smart home further? Combine Tasmota rules with MQTT integration to Home Assistant for the ultimate hybrid automation system — local intelligence where it matters, coordinated control where you need it.
