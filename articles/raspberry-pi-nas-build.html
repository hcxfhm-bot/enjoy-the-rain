How to Build a Home NAS with Raspberry Pi: OpenMediaVault Complete Setup Guide

📅 June 14, 2026 ⏱️ 15 min read ✍️ 3D Print Starter Team
💾

Cloud storage subscriptions add up fast — $10/month for Google One, $12/month for iCloud+, $15/month for Dropbox Pro. Over three years, that's $360–$540 for something you can build yourself for under $100. A home NAS (Network Attached Storage) gives you full control over your data, no subscription fees, no privacy concerns, and storage that grows when you need it.

A Raspberry Pi running OpenMediaVault (OMV) is the simplest way to build a NAS that actually works. OMV is a lightweight, Debian-based NAS operating system with a web interface for managing shares, users, backups, and services — no command-line wrangling required after the initial setup. This guide walks through the entire build: choosing hardware, installing OMV, configuring storage pools, setting up file sharing, and optimizing performance.

Why Build a NAS Instead of Using Cloud Storage?

Before diving into the build, let's address the real question: is a DIY NAS worth it compared to cloud?

FeatureCloud StorageDIY NAS
Monthly cost$10–$15/monthFree (electricity ~$1/month)
Storage limit2TB max typicallyWhatever drives you buy
PrivacyData on someone else's servers100% local, your control
SpeedDepends on internet speedLocal network: 100+ MB/s
Uptime99.9% (provider SLA)Depends on your setup
Access anywhereBuilt-inRequires VPN or remote setup
RedundancyProvider handles backupsYou handle RAID/backup

A DIY NAS wins on cost, capacity, privacy, and speed. It loses on convenience for remote access and reliability if you don't set up redundancy. For most home users who want to backup family photos, share files between devices, and store media, a Pi NAS is more than sufficient — and the satisfaction of building it yourself is a bonus.

What You'll Need

Computing

  • Raspberry Pi 4 (4GB or 8GB) or Pi 5 — The Pi 4 handles NAS duties well for 1–2 drives. The Pi 5's faster I/O makes it noticeably better for multi-drive setups and simultaneous access from several devices. If you're also running Home Assistant on the same Pi, go for the 8GB model to avoid memory pressure.
  • MicroSD card (8GB+) — Only for the OS. Your data lives on external drives. A small, reliable card like SanDisk Extreme 16GB is plenty.
  • Official power supply — 5V 3A for Pi 4, 5V 5A for Pi 5. External HDDs draw significant power; an underrated supply causes random crashes.
  • Ethernet connection — Do not use WiFi for a NAS. Gigabit ethernet (built into Pi 4/5) is essential for acceptable transfer speeds.

Storage

  • External USB hard drives (2.5" or 3.5") — The simplest approach. 2.5" drives are bus-powered (no extra power supply needed) and work well with 1–4TB capacities. 3.5" drives need a powered USB hub or external enclosure but offer better value at 4TB+.
  • USB SSDs — Faster and more reliable than HDDs, but more expensive per TB. A 1TB USB SSD costs $70–$90 vs a 2TB HDD at $50–$60. SSDs are worth it if speed matters (media streaming, frequent access).
  • Powered USB hub (if using 3.5" drives) — A 4-port hub with its own power supply. The Pi's USB ports can't provide enough power for 3.5" drives. Look for one rated at 2A+ per port.

Optional but Recommended

  • Case with passive cooling — A NAS runs 24/7. The Geekworm X825 or similar NAS case holds the Pi and a 2.5" drive in a compact enclosure. You can also 3D print a custom NAS enclosure — several designs are available on Printables and Thingiverse.
  • UPS or battery backup — Prevents data corruption from sudden power loss. A basic USB battery pack works if you wire it correctly, or use a small APC UPS.

Step 1: Install OpenMediaVault

OMV offers two installation methods: a dedicated image (easiest) or installing on top of Raspberry Pi OS (more flexible). We'll use the dedicated image method since it's the most straightforward for a NAS-only build.

Flash the OMV Image

  1. Download Raspberry Pi Imager on your computer.
  2. In the Imager, click "Choose OS" → "Other general-purpose OS" → find OpenMediaVault. If it's not listed, download the latest OMV image from the OMV Raspberry Pi releases page and use "Use custom" in the Imager.
  3. Select your microSD card and write the image.
  4. Insert the card into the Pi, connect ethernet, and power it on.
  5. Wait 2–3 minutes for the first boot to complete. OMV auto-configures the network.

Alternative: Install OMV on Raspberry Pi OS

If you want to run OMV alongside other services (like Home Assistant or OctoPrint for your 3D printer), install OMV on top of a standard Raspberry Pi OS:

# Flash Raspberry Pi OS Lite (64-bit)
# SSH into the Pi after boot, then:

sudo apt update && sudo apt upgrade -y

# Install OMV
sudo wget -O /usr/bin/omv-install https://github.com/OpenMediaVault-Plugin-Developers/installScript/raw/master/install
sudo chmod +x /usr/bin/omv-install
sudo omv-install

The install script takes 10–15 minutes and configures everything automatically. After it finishes, OMV is ready at http://your-pi-ip.

Step 2: Access the OMV Web Interface

Find your Pi's IP address by checking your router's DHCP table, or plug a monitor into the Pi briefly — it displays the IP on the console. Open a browser and navigate to http://YOUR_PI_IP.

Default login credentials:

  • Username: admin
  • Password: openmediavault

Change the password immediately after first login: go to System → Settings → Web Interface → Password. This is the most important security step — the default password is publicly known.

Step 3: Configure Storage

Connect and Mount Your Drives

Plug your external drive(s) into the Pi's USB ports. In OMV:

  1. Go to Storage → Disks — You should see your USB drive listed. If not, check the USB connection and power.
  2. Go to Storage → File Systems — Click "Create" to format the drive. Choose EXT4 for Linux-only environments (best performance and reliability). Choose NTFS if you need to occasionally plug the drive into a Windows machine directly.
  3. After creating the file system, click "Mount" to mount it.
  4. Verify it's mounted by checking the "Referenced" column shows a green checkmark.

Warning: Formatting a drive erases all data on it. If the drive has existing data you want to keep, back it up first or use OMV's mount-only approach (mount without formatting).

RAID Setup (Optional, for Multi-Drive Redundancy)

If you have two or more drives of the same size, you can create a RAID array for redundancy:

  1. Go to Storage → RAID → Click "Create"
  2. Select RAID level: RAID 1 (mirroring — one drive fails, your data survives) is recommended for home NAS. RAID 5 requires 3+ drives.
  3. Select your drives and click "Create".
  4. Wait for the RAID to initialize (can take hours for large drives — check progress in the RAID panel).
  5. Create a file system on the RAID array, then mount it.

RAID is not backup. RAID protects against drive failure, but it doesn't protect against accidental deletion, corruption, or theft. You still need a separate backup strategy (covered later).

Step 4: Create Shared Folders

Shared folders are what other devices on your network can access. Create them based on how you want to organize your data:

  1. Go to Storage → Shared Folders → Click "Add"
  2. Configure each folder:
Folder NamePurposePermissions
PhotosFamily photo backupRead/Write for family users
DocumentsWork and personal docsRead/Write for owner, Read for others
MediaMovies, music, TV showsRead-only for most users
BackupsDevice backups (Time Machine, etc.)Write-only for backup accounts
3D-Files3D print models and G-codeRead/Write for maker users

For each shared folder, select the file system (your mounted drive or RAID array) and set the path. OMV creates the directory automatically.

Step 5: Set Up File Sharing Services

SMB/CIFS (Windows, macOS, Linux)

SMB is the universal file sharing protocol — every OS supports it natively:

  1. Go to Services → SMB/CIFS → Enable the service
  2. Go to Services → SMB/CIFS → Shares → Add each shared folder
  3. For each share, set:
    • Shared folder — Select from your created folders
    • Public — "No" (require authentication) or "Yes" (guest access, use for Media)
    • Read only — Enable for Media, disable for Photos/Documents
  4. Click "Apply" to activate all changes.

On your Windows PC, the NAS appears in File Explorer under "Network" or by typing \\YOUR_PI_IP in the address bar. On macOS, it shows in Finder → Network, or use Connect to Server: smb://YOUR_PI_IP.

NFS (Linux-only, Faster)

If you have Linux devices, NFS offers better performance than SMB:

  1. Go to Services → NFS → Enable
  2. Add shares with the same shared folders
  3. Set client permissions (read/write or read-only)
  4. On your Linux machine: sudo mount YOUR_PI_IP:/export/Photos /mnt/nas-photos

SSH/SFTP (Secure Remote Access)

OMV includes SSH by default. SFTP provides secure, encrypted file transfer from anywhere — no VPN needed if you have port forwarding set up (use port 22 or a non-standard port for security). This is your primary remote access method for files.

Step 6: User Management

Create separate users for different family members and devices:

  1. Go to Access Control → User → Click "Add"
  2. Create users like: dad, mom, backup, media-player
  3. Set passwords and group memberships
  4. Go to Access Control → Shared Folder Permissions to assign read/write access per folder per user

For example, the backup user gets write-only access to the Backups folder (your backup software authenticates with this account). The media-player user gets read-only access to Media (for streaming boxes like Roku or Apple TV).

Step 7: Enable Time Machine Backup (macOS)

If you have Macs in the house, OMV can serve as a Time Machine destination — no more paying for iCloud backup or buying a Time Capsule:

  1. Create a shared folder called "TimeMachine"
  2. Go to Services → SMB/CIFS → Shares → Edit the TimeMachine share
  3. Enable "Time Machine support" and set the maximum sparse bundle size (e.g., 500GB per Mac)
  4. On your Mac: System Settings → General → Time Machine → Add Backup Disk → select your Pi NAS

Time Machine works reliably over SMB. The only caveat: first backups are large and slow over WiFi. Plug your Mac into ethernet for the initial backup (which can take hours for a full disk), then subsequent incremental backups work fine over WiFi.

Step 8: Performance Optimization

USB Drive Tuning

The Pi's USB 3.0 ports (Pi 4/5) support transfer speeds of 300–400 MB/s with SSDs, but HDDs typically deliver 80–120 MB/s. A few tweaks improve performance:

# Disable USB autosuspend (prevents drives from spinning down mid-transfer)
sudo nano /etc/default/openmediavault

# Add or modify:
OMV_USB_AUTOSUSPEND__ENABLED="false"

For SSDs, enable the fstrim timer to maintain long-term performance:

sudo systemctl enable fstrim.timer
sudo systemctl start fstrim.timer

SMB Protocol Version

In OMV's SMB settings, set the minimum protocol version to SMB3 for best performance with modern clients. SMB1 is slow and insecure — disable it:

  1. Services → SMB/CIFS → Settings → "Minimum protocol version" → SMB3
  2. Enable "Extended attributes" for better macOS compatibility

Network Optimization

  • Use gigabit ethernet — The Pi 4/5 has gigabit ethernet. Verify your router and switch also support gigabit. A 100Mbps switch caps transfers at ~12 MB/s; gigabit gives you 100+ MB/s.
  • MTU tuning (advanced) — If your network supports jumbo frames (MTU 9000), enable it on the Pi and your switch for 20–30% faster large file transfers.
  • Static IP — Set a static IP for the Pi in OMV (System → Network → Interfaces) or on your router. A DHCP address that changes breaks SMB connections and Time Machine.

Step 9: Backup Strategy

Your NAS stores your data, but what backs up your NAS? Three approaches:

Option A: Cloud Sync (Hybrid Backup)

Install the OMV CloudSync plugin to mirror important folders to a cloud provider (Backblaze B2 at $0.005/GB/month is the cheapest). This gives you off-site redundancy for disaster recovery without storing everything in the cloud.

Option B: rsync to a Second Drive

Plug a second USB drive into the Pi and set up an rsync job in OMV (System → Scheduled Jobs) to copy your primary drive weekly:

rsync -av --delete /srv/dev-disk-by-label-Primary/ /srv/dev-disk-by-label-Backup/

This is the cheapest redundancy — a second $50 HDD that sits in the same Pi and gets updated automatically.

Option C: Snapshots (ZFS/Btrfs)

If you're comfortable with advanced file systems, OMV supports Btrfs with snapshot support. Snapshots let you "undo" accidental deletions by restoring a previous state. This requires reformatting your drives as Btrfs, so plan ahead.

Step 10: 3D Print a NAS Enclosure

A bare Pi with drives hanging off USB cables looks messy and collects dust. A proper enclosure protects hardware and looks professional. You can 3D print a custom case designed for the Pi plus one or two drives.

Recommended designs to search on Printables/Thingiverse:

  • "Raspberry Pi NAS case" — Several designs hold a Pi 4 and a 2.5" HDD inside a compact shell
  • "Geekworm NAS case" — Compatible with the X825 SATA adapter board (adds SATA connectivity for better HDD performance than USB-SATA bridges)
  • "Pi 5 server rack" — Multi-Pi rack designs for people running several Pis as micro servers

Print settings for NAS enclosures:

  • Material: PETG or ABS (better heat resistance than PLA for a device running 24/7)
  • Infill: 30% (structural but not heavily loaded)
  • Layer height: 0.2mm — functional part, no need for ultra-fine resolution

Optional Plugins Worth Installing

OMV's plugin ecosystem extends your NAS well beyond basic file sharing:

  • OMV-Docker — Run Docker containers on your NAS. Perfect for running services like Plex (media server), Nextcloud (self-hosted cloud), or Home Assistant alongside your NAS.
  • OMV-FlashMemory — Reduces microSD card wear by redirecting writes to RAM. Essential for 24/7 operation — microSD cards die quickly under constant writes without this plugin.
  • OMV-ClamAV — Antivirus scanning for shared folders. Lightweight and only scans on schedule, not in real-time.
  • OMV-WOL — Wake-on-LAN support to power on the NAS remotely from another device.
  • OMV-USBBackup — One-click backup to an external USB drive with scheduled jobs.

Integrating Your NAS with Smart Home

A NAS isn't just storage — it's the backbone of a smart home infrastructure:

  • Home Assistant backup — Home Assistant can auto-backup to your NAS via SMB. Configure in HA → Settings → System → Backups → Network Storage.
  • ESPHome firmware storage — Store your ESPHome compiled firmware files on the NAS for easy OTA deployment to your ESP32 devices.
  • 3D print file server — Use your NAS as a G-code repository for OctoPrint. Point OctoPrint's upload directory at an SMB share on your NAS, so all your sliced models are centralized.
  • Media server — Install Plex or Jellyfin via Docker to stream your media collection to any device in the house.

Common Problems and Fixes

Drive Disappears After Reboot

USB drive order changes on reboot. Fix by using by-label or by-id references instead of /dev/sda. OMV handles this automatically if you configure through the web interface. If a drive still drops, check the USB cable and power supply.

Slow Transfer Speeds

Verify you're on gigabit ethernet (not WiFi). Check SMB protocol version (must be SMB3+). If using HDDs, they're inherently slower than SSDs — 80–120 MB/s is normal. For SSDs, check that the USB connection is USB 3.0 (blue port on Pi 4).

OMV Web Interface Won't Load

Check the Pi's IP hasn't changed (set a static IP). Try SSH access (ssh root@PI_IP — OMV's default root password is the same as the web admin password). Restart OMV services: sudo systemctl restart openmediavault-engined.

MicroSD Card Corrupted

Install the FlashMemory plugin immediately on any new OMV setup. Without it, constant log writes kill microSD cards in weeks. If your card is already corrupted, reflash it, install FlashMemory, and restore your OMV configuration from a backup.

What's Next?

Once your NAS is running, these upgrades make it even more powerful:

  • Plex media server — Stream your movie and music collection to any TV, phone, or tablet in the house. Install via Docker on the Pi.
  • Nextcloud — Self-hosted Google Drive alternative. Sync files across all your devices and access them from anywhere.
  • Pi-hole ad blocker — Run it on the same Pi (or another one) to block ads for your entire network. Low resource usage, runs alongside OMV fine.
  • Multiple drives with RAID — Add a second drive and set up RAID 1 mirroring for peace of mind. If one drive dies, your data survives.
  • Remote access via VPN — Install WireGuard or Tailscale to securely access your NAS from anywhere without exposing it to the internet.

Conclusion

Building a home NAS with Raspberry Pi and OpenMediaVault is one of the most practical maker projects you can undertake. For under $100, you get a network storage server that replaces expensive cloud subscriptions, gives you complete data sovereignty, and serves as the foundation for your smart home infrastructure.

The setup takes about an hour from flashing the SD card to having working SMB shares, and OMV's web interface makes ongoing management simple enough that you rarely need to touch the command line. Add Docker for services like Plex and Home Assistant, 3D print a clean enclosure, and you've built something that rivals commercial NAS devices at a fraction of the cost — with the satisfaction of knowing exactly how every piece works.
