Tasmota MQTT Setup: Connect Your Devices to Home Assistant

📅 July 9, 2026 ⏱️ 8 min read ✍️ 3D Print Starter Team
🔌

MQTT is the backbone of any robust smart home setup, and Tasmota MQTT configuration is your gateway to seamlessly connecting ESP-based devices to Home Assistant. Whether you've just flashed Tasmota on a Sonoff switch or you're building custom ESP32 sensors, understanding MQTT integration transforms basic Wi-Fi devices into powerful, locally-controlled smart home components.

In this guide, I'll walk you through the complete Tasmota MQTT setup process—from broker configuration to Home Assistant auto-discovery—so you can control your devices without relying on cloud services.

Why Use MQTT with Tasmota?

MQTT (Message Queuing Telemetry Transport) is a lightweight messaging protocol perfect for IoT devices. When combined with Tasmota, it offers significant advantages:

  • Local control — No internet required, your smart home works even without cloud connectivity
  • Fast response — Near-instant device control and status updates
  • Low bandwidth — Minimal network overhead, ideal for devices like ESP8266
  • Scalability — One MQTT broker can handle hundreds of devices
  • Integration flexibility — Connect to Home Assistant, Node-RED, openHAB, or custom scripts

For makers building DIY smart home projects—whether it's a DIY smart door lock or monitoring a Raspberry Pi NAS—MQTT provides the communication layer that ties everything together.

Prerequisites

Before configuring Tasmota MQTT, ensure you have:

  • Tasmota-flashed device — Follow our complete Tasmota flashing guide if you haven't done this yet
  • MQTT broker — Home Assistant's Mosquitto add-on, standalone Mosquitto, or cloud broker like HiveMQ
  • Home Assistant — Already set up with MQTT integration (we'll cover this)
  • Network access — Your Tasmota device and MQTT broker on the same network

If you're new to Home Assistant, start with our Raspberry Pi Home Assistant setup guide.

Step 1: Set Up an MQTT Broker

Option A: Home Assistant Mosquitto Add-on (Recommended)

If you're running Home Assistant OS or Supervised, the Mosquitto broker add-on is the easiest option:

  1. Go to Settings → Add-ons → Add-on Store
  2. Search for "Mosquitto broker" and click Install
  3. Before starting, configure authentication:
    • Go to Configuration tab
    • Leave defaults for basic setup
  4. Start the add-on and enable "Watchdog" for auto-restart

Home Assistant's Mosquitto integrates seamlessly with Home Assistant users—your HA login credentials work automatically.

Option B: Standalone Mosquitto Broker

For advanced setups or non-Home Assistant environments, install Mosquitto on a Linux server or Raspberry Pi:

sudo apt update
sudo apt install mosquitto mosquitto-clients
sudo systemctl enable mosquitto
sudo systemctl start mosquitto

Create a user for Tasmota devices:

sudo mosquitto_passwd -c /etc/mosquitto/passwd tasmota_user
# Enter password when prompted

Edit Mosquitto configuration to require authentication:

sudo nano /etc/mosquitto/mosquitto.conf

# Add these lines:
allow_anonymous false
password_file /etc/mosquitto/passwd
listener 1883

Restart Mosquitto:

sudo systemctl restart mosquitto

Step 2: Configure MQTT in Home Assistant

With Mosquitto running, add the MQTT integration to Home Assistant:

  1. Go to Settings → Devices & Services
  2. Click Add Integration (bottom right)
  3. Search for "MQTT" and select it
  4. Enter your broker details:
    • Broker — Home Assistant IP or "core-mosquitto" if using the add-on
    • Port — 1883 (default)
    • Username — Your Home Assistant username (for add-on) or Mosquitto user
    • Password — Corresponding password
  5. Click Submit to connect

If successful, you'll see "MQTT" in your integrations list with a green checkmark.

Step 3: Configure Tasmota MQTT Settings

Now connect your Tasmota device to the MQTT broker:

  1. Access your Tasmota device's web interface (enter its IP in your browser)
  2. Go to Configuration → Configure MQTT
  3. Enter your MQTT settings:
    • Host — Your MQTT broker IP (e.g., 192.168.1.100 or Home Assistant IP)
    • Port — 1883
    • User — MQTT username (leave blank if no auth)
    • Password — MQTT password
    • Client — Unique identifier (e.g., "sonoff_livingroom")
    • Topic — Base topic for this device (e.g., "sonoff_lr")
    • Full Topic — Leave as default "%prefix%/%topic%/"
  4. Click Save

The device will restart. After reboot, verify MQTT connection in the Tasmota console:

Status 5

Look for "MQTT" showing "Connected" with your broker IP.

Step 4: Enable Home Assistant Auto-Discovery

Tasmota can automatically create entities in Home Assistant using MQTT auto-discovery. This is the easiest way to integrate devices.

Enable Auto-Discovery in Tasmota

In the Tasmota console, run:

SetOption19 1

Restart the device:

Restart 1

After reboot, check Home Assistant:

  1. Go to Settings → Devices & Services → MQTT
  2. Click "Configure" on the MQTT integration
  3. Look for new devices in the "MQTT" section
  4. Your Tasmota device should appear with entities (switch, sensor, etc.)

For most basic devices like Sonoff switches, auto-discovery creates:

  • Switch entity — Control power state
  • Sensor entities — WiFi signal, uptime (if enabled)
  • Energy sensors — For POW devices with energy monitoring

For devices with energy monitoring, see our Tasmota energy monitoring guide.

Step 5: Manual MQTT Configuration (Advanced)

For custom setups or when auto-discovery doesn't meet your needs, manually configure MQTT entities in Home Assistant's configuration.yaml:

Manual Switch Configuration

mqtt:
  switch:
    - name: "Living Room Light"
      state_topic: "stat/sonoff_lr/POWER"
      command_topic: "cmnd/sonoff_lr/POWER"
      payload_on: "ON"
      payload_off: "OFF"
      state_on: "ON"
      state_off: "OFF"

Manual Sensor Configuration

mqtt:
  sensor:
    - name: "Living Room Temperature"
      state_topic: "tele/sonoff_lr/SENSOR"
      value_template: "{{ value_json.Temperature }}"
      unit_of_measurement: "°C"

Understanding Tasmota MQTT Topics

Tasmota uses a structured topic format:

Prefix Purpose Example
cmnd Commands sent to device cmnd/sonoff_lr/POWER
stat Device status responses stat/sonoff_lr/POWER
tele Telemetry data (periodic) tele/sonoff_lr/SENSOR

For example, to turn on a device via MQTT:

# Publish to:
cmnd/sonoff_lr/POWER

# Payload:
ON

Step 6: Verify MQTT Communication

Test your setup using MQTT tools:

Using Home Assistant Developer Tools

  1. Go to Developer Tools → MQTT
  2. In "Listen to a topic", enter # (wildcard to see all messages)
  3. Click "Start Listening"
  4. Toggle your Tasmota device—you should see MQTT messages appear

Using Mosquitto CLI Clients

Subscribe to all Tasmota messages:

mosquitto_sub -h BROKER_IP -u USERNAME -P PASSWORD -t "#"

Test publishing a command:

mosquitto_pub -h BROKER_IP -u USERNAME -P PASSWORD -t "cmnd/sonoff_lr/POWER" -m "ON"

Creating Automations with Tasmota MQTT

With MQTT configured, create powerful Home Assistant automations. Here are practical examples:

Example 1: Button Press Automation

Trigger actions when a Tasmota device's button is pressed:

alias: "Button Press - Toggle Living Room"
trigger:
  - platform: mqtt
    topic: "stat/sonoff_button/POWER"
    payload: "ON"
action:
  - service: light.toggle
    target:
      entity_id: light.living_room

Example 2: Periodic Telemetry Logging

Tasmota sends telemetry data every 5 minutes (configurable). Use this for monitoring:

alias: "Log Low WiFi Signal"
trigger:
  - platform: mqtt
    topic: "tele/sonoff_lr/STATE"
condition:
  - condition: template
    value_template: "{{ trigger.payload_json.Wifi.RSSI | int < -70 }}"
action:
  - service: notify.mobile_app
    data:
      message: "Poor WiFi signal on sonoff_lr: {{ trigger.payload_json.Wifi.RSSI }} dBm"

Tasmota MQTT Configuration Commands Reference

Essential console commands for MQTT configuration:

Command Function
MqttHost <ip> Set MQTT broker IP
MqttPort <port> Set MQTT broker port
MqttUser <user> Set MQTT username
MqttPassword <pass> Set MQTT password
Topic <name> Set device topic
SetOption19 1 Enable Home Assistant auto-discovery
TelePeriod <seconds> Set telemetry interval (default 300)
Status 5 Show MQTT status

Troubleshooting Common MQTT Issues

Tasmota shows "MQTT: Disconnected"

Verify broker IP, username, and password. Check if the broker is running. For Home Assistant Mosquitto, ensure the add-on is started. Test connectivity with Ping <broker_ip> in Tasmota console.

Home Assistant doesn't discover the device

Confirm SetOption19 1 is enabled. Check Home Assistant's MQTT integration is active. Restart the Tasmota device after enabling auto-discovery. Verify the device's MQTT topic doesn't conflict with existing devices.

Commands sent but device doesn't respond

Verify command topic format: cmnd/<topic>/POWER. Check payload is exactly "ON" or "OFF" (case-sensitive). Use MQTT listener to see if messages arrive at the device.

Intermittent disconnections

Check WiFi signal strength (Status 11 in console). Increase MQTT keepalive with MqttKeepAlive 60. Consider using static IP for the device.

Multiple devices with same topic conflict

Each Tasmota device needs a unique topic. Use descriptive names like "sonoff_kitchen", "sonoff_bedroom" rather than generic "sonoff1", "sonoff2".

For systematic troubleshooting approaches, see our troubleshooting methodology guide—the same principles apply.

Best Practices for Tasmota MQTT Setup

  • Use descriptive topics — "sonoff_livingroom_main" is better than "sonoff1"
  • Enable MQTT logging — LogPort 1883 sends logs via MQTT for debugging
  • Set appropriate TelePeriod — Balance between data freshness and network traffic
  • Use MQTT retain flag — Devices remember last state after restart (SetOption20 1)
  • Group related devices — Use consistent topic naming for easier management
  • Secure your broker — Always use authentication, especially if exposed to the internet

Advanced MQTT: Retained Messages and LWT

Last Will and Testament (LWT)

Tasmota automatically configures LWT—messages published when the device disconnects unexpectedly. This appears in Home Assistant as an "availability" topic. Devices show "unavailable" instead of "unknown" when offline.

Retained Messages

Enable retained messages so devices remember their state after power loss:

SetOption20 1

This stores the last state in the MQTT broker, so devices report correct state immediately after restart.

Integrating Custom ESP32/ESP8266 Projects

Tasmota MQTT isn't just for Sonoff devices. You can flash Tasmota on generic ESP32 boards for custom projects:

  • Temperature sensors — Combine with ESPHome sensors for Home Assistant
  • Relay controllers — Build custom switch panels
  • RGB controllers — Control LED strips with Tasmota's lighting features
  • Garage door controllers — Monitor and control garage doors

Tasmota MQTT configuration unlocks the full potential of your smart home devices. With local control, fast response times, and seamless Home Assistant integration, you get professional-grade smart home functionality without monthly fees or cloud dependencies.
