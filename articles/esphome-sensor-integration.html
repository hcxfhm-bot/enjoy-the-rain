ESPHome Sensor Integration: DHT22, BME280, and Analog Sensors with Home Assistant

📅 June 24, 2026 ⏱️ 15 min read ✍️ 3D Print Starter Team
🌡️

You've got ESPHome running on your ESP32 or ESP8266. Now it's time to make it actually do something useful. The most common first project? Environmental sensors. Temperature, humidity, pressure — the bread and butter of any smart home.

In this guide, I'll walk you through integrating three popular sensor types with ESPHome: the budget-friendly DHT22, the precision BME280, and basic analog sensors. By the end, you'll have real sensor data flowing into Home Assistant and ready for automations.

If you haven't set up ESPHome yet, start with our ESPHome Getting Started Guide to get your board flashed and connected.

Why Sensor Choice Matters

Not all sensors are created equal. Here's a quick comparison of the two most popular temperature/humidity sensors:

Feature DHT22 (AM2302) BME280
Price $2-5 $5-15
Temperature Accuracy ±0.5°C ±0.5°C
Humidity Accuracy ±2-5% ±3%
Pressure Sensing ❌ No ✅ Yes (±1 hPa)
Update Speed ~2 seconds Instant (I2C)
Interface 1-wire digital I2C or SPI

Bottom line: DHT22 is fine for basic "is it hot in here?" sensing. BME280 is worth the extra cost if you want barometric pressure data or better accuracy for climate control automations.

Part 1: DHT22 Temperature & Humidity Sensor

The DHT22 is the classic beginner sensor. It's cheap, widely available, and dead simple to wire. The tradeoff? It's slower to update and less accurate than premium sensors.

Wiring the DHT22

The DHT22 has three pins you'll use (some modules have 4 pins, but one is unused):

  • VCC → ESP32 3.3V pin (or 5V if your module has a voltage regulator)
  • DATA → Any GPIO pin (I'll use GPIO 21)
  • GND → ESP32 GND

Most DHT22 modules include a built-in pull-up resistor on the data line. If you're using a bare DHT22 sensor (the white plastic blob with 4 pins), you'll need to add a 4.7KΩ resistor between VCC and DATA.

ESPHome Configuration for DHT22

Add this to your ESPHome YAML config:

sensor:
  - platform: dht
    pin: GPIO21
    temperature:
      name: "Living Room Temperature"
      id: living_room_temp
    humidity:
      name: "Living Room Humidity"
      id: living_room_humidity
    update_interval: 60s
    model: DHT22

Key settings explained:

  • pin: GPIO21 — The GPIO pin connected to the DATA line. Change this to match your wiring.
  • update_interval: 60s — How often to read the sensor. DHT22 can't update faster than every 2 seconds, so 60s saves power and reduces noise.
  • model: DHT22 — Tells ESPHome which DHT variant you're using. Options: DHT11, DHT22, DHT22_TYPE2, AM2302, RHT03.

Testing Your DHT22

After uploading the config to your ESP32:

  1. Open Home Assistant → Settings → Devices & Services
  2. Find your ESPHome device (it should appear automatically)
  3. Click it to see the sensor entities
  4. You should see "Living Room Temperature" and "Living Room Humidity" with current values

If sensors show "unknown" or "NAN":

  • Check wiring (most common issue — DATA pin is easy to mix up)
  • Try a different GPIO pin (some pins on ESP32 have special uses)
  • Add a pull-up resistor if using a bare sensor (not a module)
  • Check ESPHome logs for error messages

Part 2: BME280 Temperature, Humidity & Pressure Sensor

The BME280 is my go-to sensor for serious environmental monitoring. It measures temperature, humidity, and barometric pressure, all with better accuracy and faster updates than the DHT22. The I2C interface means it shares two pins with other I2C devices.

Wiring the BME280

BME280 modules use I2C, which requires only two data pins:

  • VCC → ESP32 3.3V (most BME280 modules are 3.3V only — don't connect to 5V!)
  • GND → ESP32 GND
  • SCL → ESP32 GPIO 22 (default I2C clock pin)
    • SDA → ESP32 GPIO 21 (default I2C data pin)

These are the default I2C pins on ESP32. You can use different pins by configuring them in ESPHome.

ESPHome Configuration for BME280

First, set up I2C in your config:

i2c:
  sda: GPIO21
  scl: GPIO22
  scan: true

Then add the BME280 sensor:

sensor:
  - platform: bme280_i2c
    temperature:
      name: "Office Temperature"
      id: office_temp
      oversampling: 16x
    humidity:
      name: "Office Humidity"
      id: office_humidity
      oversampling: 16x
    pressure:
      name: "Office Pressure"
      id: office_pressure
      oversampling: 16x
    address: 0x76
    update_interval: 60s

Important settings:

  • address: 0x76 — The default I2C address for most BME280 modules. Some use 0x77. If you're not sure, check the module documentation or run I2C scan (set scan: true in the i2c config and check logs).
  • oversampling: 16x — Higher oversampling = more accurate readings but slower. Options: NONE, 1x, 2x, 4x, 8x, 16x. 16x is overkill for most uses; 4x or 8x is a good balance.

Getting Useful Pressure Data

Raw barometric pressure is interesting for weather monitoring, but it's hard to interpret directly. Here's how to convert it to sea-level equivalent (what weather apps report):

  - platform: template
    name: "Office Pressure Sea Level"
    lambda: |-
      const float ALTITUDE = 150; // Your altitude in meters
      return id(office_pressure).state * 
        pow(1 - (0.0065 * ALTITUDE / 288.15), -5.255);
    unit_of_measurement: "hPa"
    device_class: pressure
    update_interval: 60s

Replace ALTITUDE = 150 with your actual elevation in meters. You can find this from Google Maps or your phone's compass app.

Part 3: Analog Sensors (Light, Soil Moisture, Gas)

ESP32 has built-in analog-to-digital converters (ADC) that can read voltage levels from 0-3.3V. This opens up a huge range of cheap analog sensors: light sensors, soil moisture probes, gas sensors, and more.

ESP32 ADC Gotchas

Before wiring analog sensors, understand these ESP32 limitations:

  • ADC2 pins don't work when WiFi is enabled: GPIO 0, 2, 4, 12-15, 25-27 are on ADC2. Use ADC1 pins instead (GPIO 32-39).
  • Non-linear response: ESP32 ADC isn't perfectly linear. For precision projects, calibrate with known voltages.
  • Noise: ESP32 ADC is noisy. ESPHome includes averaging and oversampling to help.
  • Input range: 0-3.3V max. Higher voltages will damage the pin.

Example: Simple Light Sensor (LDR)

A light-dependent resistor (LDR) changes resistance based on light. Wire it in a voltage divider with a 10KΩ fixed resistor:

  • 3.3V → LDR → GPIO 34 (ADC pin)
  • GPIO 34 → 10KΩ resistor → GND

ESPHome config:

sensor:
  - platform: adc
    pin: GPIO34
    name: "Ambient Light"
    attenuation: 11db
    update_interval: 10s
    filters:
      - multiply: 100
      - sliding_window_moving_average:
          window_size: 5
          send_every: 5

Config breakdown:

  • attenuation: 11db — Extends input range to ~0-3.3V. Options: 0db (0-1.1V), 2.5db (0-1.5V), 6db (0-2.2V), 11db (0-3.3V).
  • multiply: 100 — Scales the 0-3.3V reading to 0-100 for a "percentage" output.
  • sliding_window_moving_average — Takes 5 readings and averages them to reduce noise.

Example: Soil Moisture Sensor

Cheap capacitive soil moisture sensors output 0-3.3V based on soil moisture. Wire the sensor's analog output to an ADC pin (GPIO 32, for example):

sensor:
  - platform: adc
    pin: GPIO32
    name: "Plant Soil Moisture"
    attenuation: 11db
    update_interval: 60s
    filters:
      - median:
          window_size: 3
          send_every: 3
      - calibrate_linear:
          - 0.0 -> 100.0
          - 3.3 -> 0.0

The calibrate_linear filter inverts the reading (higher voltage = drier soil on most sensors) and scales to 0-100%. For accuracy, measure the actual voltages in dry and water-saturated soil, then adjust the calibration points.

Part 4: Using Sensor Data in Home Assistant Automations

Now that your sensors are reporting to Home Assistant, put them to work. Here are three practical automation examples:

Automation 1: Alert When Temperature Drops Below Threshold

alias: "Alert: Low Temperature"
trigger:
  - platform: numeric_state
    entity_id: sensor.living_room_temperature
    below: 15
action:
  - service: notify.mobile_app_your_phone
    data:
      title: "⚠️ Low Temperature Alert"
      message: "Living room is {{ states('sensor.living_room_temperature') }}°C"

Automation 2: Turn On Humidifier When Humidity Drops

alias: "Humidifier: Auto On"
trigger:
  - platform: numeric_state
    entity_id: sensor.office_humidity
    below: 40
action:
  - service: switch.turn_on
    target:
      entity_id: switch.humidifier

Part 5: Troubleshooting Common Sensor Issues

DHT22 Shows "NAN" or Updates Very Slowly

  • Wrong pin: Double-check DATA pin connection and GPIO number in config
  • Missing pull-up resistor: Add 4.7KΩ between VCC and DATA if using bare sensor
  • 3.3V vs 5V: Most DHT22 modules work at 3.3V, but check your specific module
  • Bad sensor: DHT22 clones are common and often fail. Try a different sensor.

BME280 Not Detected (I2C Error)

  • Wrong I2C address: Try 0x77 instead of 0x76 (or vice versa)
  • SDA/SCL swapped: The two I2C pins are easy to mix up
  • Voltage issue: BME280 is strictly 3.3V. Powering from 5V can damage it.
  • Enable I2C scan: Set scan: true in i2c config and check ESPHome logs

Analog Sensor Values Are All Over the Place

  • Use ADC1 pins: ADC2 pins (GPIO 0, 2, 4, 12-15, 25-27) don't work with WiFi enabled
  • Add filtering: Use sliding_window_moving_average or median filters
  • Check attenuation: Use 11db for 0-3.3V input range
  • Avoid breadboard: Breadboard connections are noisy. Solder connections for stable readings.

Sensors Work But Values Seem Wrong

Sensor accuracy varies. DHT22 ±2-5% humidity is typical. For more accurate readings:

  • Calibrate against a known reference (commercial weather station, medical-grade thermometer)
  • Use calibrate_linear or calibrate_polynomial filters in ESPHome
  • Average multiple sensors in the same space
  • Upgrade to a higher-quality sensor like BME280 or SHT31

Part 6: Power-Saving Tips for Battery-Powered Sensors

If you're building a battery-powered sensor node, every milliamp counts. Here's how to extend battery life:

  • Increase update_interval: 5-15 minutes is fine for temperature trends. 60 seconds drains batteries quickly.
  • Use deep sleep: ESPHome supports deep sleep mode where the ESP32 powers down between readings.
  • Disable WiFi between readings: Combine deep sleep with sensor polling to minimize WiFi uptime.
  • Choose sensors wisely: DHT22 draws less power than BME280 during readings.
  • Avoid power-hungry features: Bluetooth, always-on WiFi, and frequent display updates kill batteries.

Example deep sleep config for a 10-minute interval:

deep_sleep:
  id: deep_sleep_1
  sleep_duration: 10min

interval:
  - interval: 10min
    then:
      - deep_sleep.enter: deep_sleep_1

What's Next?

Now that you've got environmental sensors running, the smart home possibilities are endless. Here are some natural next steps:

  • Build a weather station: Combine BME280 with an anemometer and rain sensor
  • Create plant monitors: Soil moisture + light sensors for automated watering
  • Set up air quality monitoring: Add gas sensors like MQ-135 or PMS5003 particulate sensor
  • 3D print enclosures: Protect your sensors with custom 3D printed cases — see our How to 3D Print Custom Smart Home Device Cases guide

ESPHome's component library has support for hundreds of sensors, displays, and actuators. Once you understand the basic sensor integration pattern, adding new devices is just a matter of finding the right YAML config.
