How to Build a DIY Weather Station with Raspberry Pi: Complete Guide

📅 June 12, 2026 ⏱️ 12 min read ✍️ 3D Print Starter Team
🌤️

Commercial weather stations cost $150–$500 and often lock you into proprietary apps with limited data access. But with a Raspberry Pi and a handful of affordable sensors, you can build a fully custom weather station that logs real data, integrates with Home Assistant, and lets you 3D print a weatherproof enclosure that looks exactly how you want it.

This guide walks through the complete build: selecting sensors, wiring them to your Pi, writing Python code to collect and publish data, integrating everything into your smart home dashboard, and designing a custom 3D printed housing to protect your station outdoors.

What You'll Need

Core Hardware

  • Raspberry Pi 4 or 5 — Any model works; the Pi 4 (2GB) is the sweet spot for cost and performance. If you haven't set up a Pi before, start with our Raspberry Pi setup guide.
  • BME280 sensor breakout — Measures temperature, humidity, and barometric pressure in one tiny module. Around $5–$8 on AliExpress or Adafruit.
  • Wind speed sensor (anemometer) — A simple reed-switch anemometer that outputs pulses proportional to wind speed. Available for $10–$15.
  • Rain gauge — A tipping-bucket rain gauge that counts tips (each tip = 0.2mm or 0.01 inch of rain). $15–$20.
  • UV/light sensor (optional) — A VEML6075 or Si1145 breakout for UV index and ambient light. $8–$12.

Tools & Supplies

  • Soldering iron and basic soldering supplies — our soldering station guide covers everything you need
  • Jumper wires (female-to-female for Pi GPIO connections)
  • 4GB+ microSD card with Raspberry Pi OS
  • USB power supply (5V 3A minimum for Pi 4)
  • 3D printer for the enclosure — any budget FDM printer works fine
  • Weatherproof cable glands (PG7 or PG9 size)
  • PETG or ASA filament for outdoor durability (see our ASA filament guide for outdoor printing)

Total cost: Approximately $40–$70 depending on how many sensors you include. That's less than a quarter of what a commercial Davis Vantage Pro2 costs.

Sensor Wiring Guide

BME280 (I²C Connection)

The BME280 communicates via I²C, which means just four wires:

  • VIN → Pi 3.3V (Pin 1)
  • GND → Pi GND (Pin 6)
  • SDI (SDA) → Pi GPIO2 (Pin 3)
  • SCK (SCL) → Pi GPIO3 (Pin 5)

Enable I²C on your Pi with sudo raspi-config → Interface Options → I²C → Enable. Verify the sensor is detected:

sudo i2cdetect -y 1

You should see the BME280 at address 0x76 or 0x77 depending on your breakout board's default configuration.

Anemometer (GPIO Pulse Counting)

The reed-switch anemometer outputs one pulse per revolution. Wind speed is calculated from the pulse frequency. Wiring:

  • One wire → Pi 3.3V (Pin 1)
  • Other wire → Pi GPIO17 (Pin 11) with a 10kΩ pull-down resistor to GND

The pull-down resistor keeps the GPIO pin LOW between pulses. Without it, floating input reads cause false counts. If you're not comfortable soldering resistors, our soldering iron tips guide will help you get clean joints on small components.

Rain Gauge (GPIO Interrupt)

The tipping-bucket gauge works identically to the anemometer — a reed switch triggers on each tip:

  • One wire → Pi 3.3V (Pin 1)
  • Other wire → Pi GPIO27 (Pin 13) with a 10kΩ pull-down resistor to GND

Python Data Collection Code

Install the required libraries:

pip3 install bme280 smbus2 RPi.GPIO paho-mqtt

Here's the core data collection script:

#!/usr/bin/env python3
import time
import json
import bme280
import smbus2
import RPi.GPIO as GPIO
import paho.mqtt.client as mqtt

# BME280 setup
bus = smbus2.SMBus(1)
bme280.load_calibration_params(bus, 0x76)

# GPIO setup for anemometer and rain gauge
ANEMO_PIN = 17
RAIN_PIN = 27
wind_count = 0
rain_count = 0
WIND_SPEED_FACTOR = 1.2  # Adjust per your anemometer spec
RAIN_PER_TIP = 0.2  # mm per tip (check your gauge spec)

GPIO.setmode(GPIO.BCM)
GPIO.setup(ANEMO_PIN, GPIO.IN, pull_up_down=GPIO.PUD_DOWN)
GPIO.setup(RAIN_PIN, GPIO.IN, pull_up_down=GPIO.PUD_DOWN)

def wind_tick(channel):
    global wind_count
    wind_count += 1

def rain_tick(channel):
    global rain_count
    rain_count += 1

GPIO.add_event_detect(ANEMO_PIN, GPIO.RISING, callback=wind_tick)
GPIO.add_event_detect(RAIN_PIN, GPIO.RISING, callback=rain_tick, bouncetime=200)

# MQTT client for Home Assistant integration
client = mqtt.Client("weather_station")
client.connect("localhost", 1883, 60)  # Home Assistant MQTT broker

def publish_data():
    data = bme280.sample(bus, 0x76)
    wind_speed = wind_count * WIND_SPEED_FACTOR / 5  # 5-second sample
    rainfall = rain_count * RAIN_PER_TIP
    
    payload = {
        "temperature": round(data.temperature, 1),
        "humidity": round(data.humidity, 1),
        "pressure": round(data.pressure, 1),
        "wind_speed": round(wind_speed, 1),
        "rainfall": round(rainfall, 2)
    }
    
    client.publish("homeassistant/sensor/weather_station/state",
                   json.dumps(payload))
    
    global wind_count, rain_count
    wind_count = 0
    rain_count = 0

# Main loop — publish every 30 seconds
while True:
    publish_data()
    time.sleep(30)

This script reads the BME280 every 30 seconds, calculates wind speed from pulse counts, accumulates rainfall, and publishes everything to your MQTT broker. Home Assistant will auto-discover the sensor data if you configure MQTT discovery — see our Home Assistant automations guide for the full setup.

Home Assistant Integration

To display your weather data in Home Assistant, configure MQTT sensors in your configuration.yaml:

mqtt:
  sensor:
    - name: "Weather Station Temperature"
      state_topic: "homeassistant/sensor/weather_station/state"
      value_template: "{{ value_json.temperature }}"
      unit_of_measurement: "°C"
      device_class: temperature
    - name: "Weather Station Humidity"
      state_topic: "homeassistant/sensor/weather_station/state"
      value_template: "{{ value_json.humidity }}"
      unit_of_measurement: "%"
      device_class: humidity
    - name: "Weather Station Pressure"
      state_topic: "homeassistant/sensor/weather_station/state"
      value_template: "{{ value_json.pressure }}"
      unit_of_measurement: "hPa"
      device_class: atmospheric_pressure
    - name: "Weather Station Wind Speed"
      state_topic: "homeassistant/sensor/weather_station/state"
      value_template: "{{ value_json.wind_speed }}"
      unit_of_measurement: "km/h"
    - name: "Weather Station Rainfall"
      state_topic: "homeassistant/sensor/weather_station/state"
      value_template: "{{ value_json.rainfall }}"
      unit_of_measurement: "mm"

After restarting Home Assistant, all five sensors appear on your dashboard. You can create automations like: "If wind speed exceeds 50 km/h, send a notification" or "If rainfall exceeds 5mm in the last hour, close the smart blinds." These automations tie directly into the broader smart home system we covered in our ESP32 smart home projects guide.

If you want your weather data available on Apple devices, bridge Home Assistant to HomeKit using the method described in our HomeKit integration guide. Your weather station sensors will appear in the Home app alongside your other smart home devices.

3D Printed Enclosure Design

Your weather station lives outdoors, so the enclosure needs to be weatherproof, ventilated, and UV-resistant. Here's the design approach:

Enclosure Requirements

  • Material: PETG or ASA — both handle outdoor conditions better than PLA. ASA is specifically designed for UV resistance and temperature stability (see our ASA guide). PETG is easier to print and more impact-resistant.
  • Design features: Louvered sides for airflow (the BME280 needs ambient air, not trapped greenhouse heat), sloped roof to shed rain, cable gland holes for sensor wires, and a mounting bracket for a pole or wall.
  • Rain gauge placement: Mount the rain gauge separately on a flat, level surface away from trees and buildings. Don't put it inside the main enclosure — it needs open sky exposure.
  • Anemometer placement: Mount the anemometer on a mast above the enclosure, ideally 2–3 meters above ground level for accurate wind readings.

Basic Enclosure Dimensions

A simple box measuring roughly 120×100×60mm holds the Pi, BME280, and wiring. You can design this in Tinkercad in about 30 minutes — it's just a louvered box with a sloped lid. Add four cable gland holes (one for power, one for BME280 extension, one for anemometer, one for rain gauge).

For more complex enclosures with integrated mounting brackets, Fusion 360 gives you parametric control. Design the louvers as 3mm-wide slots angled at 30° — this blocks direct rain while allowing airflow. The technique is the same as printing the smart home device cases we covered earlier, just scaled up.

Print Settings for Outdoor Enclosures

  • Layer height: 0.2mm — good balance of strength and print time
  • Infill: 30–40% — walls need enough density to resist impact; Gyroid pattern for best strength distribution (see our infill patterns guide)
  • Walls: 4 perimeters (1.6mm with a 0.4mm nozzle) — thick walls resist cracking under thermal cycling
  • No enclosure needed for printing PETG/ASA — but if your printer has one, use it. Our enclosure guide explains the benefits

Data Logging and Visualization

Beyond real-time dashboard display, you'll want historical data. Two approaches:

Option A: Home Assistant Long-Term Statistics

Home Assistant automatically stores sensor history for 10 days by default. To keep data longer, configure the recorder integration in configuration.yaml:

recorder:
  purge_keep_days: 365
  include:
    domains:
      - sensor

This keeps a full year of weather data. The History dashboard shows trends, and you can export data as CSV for analysis.

Option B: Dedicated Database with Grafana

For serious data nerds, route MQTT data into InfluxDB and visualize with Grafana:

pip3 install influxdb

Add InfluxDB writes to your Python script alongside the MQTT publish. Grafana running on the same Pi (or a separate server) creates professional weather dashboards with graphs, gauges, and alerts. This is the same approach used in industrial weather monitoring — just scaled down for your home.

If you're already running your Pi as a NAS (covered in our Raspberry Pi projects guide), InfluxDB and Grafana run alongside your NAS without noticeable performance impact.

Calibration Tips

Your DIY station won't match professional accuracy out of the box, but simple calibration gets you close:

  • Temperature: The BME280 typically reads 1–2°C high due to self-heating from the IC. Reduce the sampling frequency (read every 60 seconds instead of 30) and subtract a -1°C offset in your code for a quick fix.
  • Humidity: Place the sensor in open airflow — never inside a sealed box. The BME280's humidity accuracy is ±3%, which is acceptable for home weather monitoring.
  • Pressure: BME280 pressure readings are altitude-dependent. Enter your elevation in the code to convert raw pressure to sea-level equivalent (the standard for weather reporting).
  • Wind speed: Calibrate the WIND_SPEED_FACTOR constant by comparing against a known reference — even a handheld anemometer helps. The factor varies between different anemometer models.
  • Rain gauge: Verify RAIN_PER_TIP matches your gauge's specification. Pour a known volume of water (e.g., 100ml = 1mm over a 100cm² collector area) slowly and count the tips to confirm.

Power and Reliability Considerations

A weather station runs 24/7, so reliability matters:

  • Use a quality USB power supply. Undervoltage causes Pi instability and sensor read failures. A 5V 3A supply with a short, thick cable is essential.
  • Add a watchdog. Configure the Pi's hardware watchdog to reboot automatically if the Python script crashes or the Pi hangs:
# Enable watchdog in /boot/config.txt
dtparam=watchdog=on

# Add to your systemd service for auto-restart on failure
Restart=always
RestartSec=10
  • Run the script as a systemd service so it starts automatically on boot and restarts on crash. Create /etc/systemd/system/weather-station.service with the standard service configuration pointing to your Python script.
  • Consider a UPS or battery backup for the Pi if your area has frequent power outages. A simple USB battery pack between the power supply and Pi provides 2–4 hours of backup.

FAQ: DIY Weather Station Questions

Can I use an Arduino instead of a Raspberry Pi? Yes, but you lose the ability to run Home Assistant, MQTT broker, and a database on the same device. An Arduino works well as a remote sensor node that sends data to a Pi-based server. Our Arduino vs Raspberry Pi comparison covers the tradeoffs in detail.

How accurate is a DIY weather station? With calibrated BME280 sensors and proper mounting, temperature accuracy reaches ±0.5°C, humidity ±3%, and pressure ±1 hPa — comparable to mid-range commercial stations. Wind and rain accuracy depends more on sensor quality and placement than on the Pi itself.

Can I add more sensors later? Absolutely. The I²C bus supports multiple devices, and you have plenty of GPIO pins for additional pulse-count sensors. Common additions include soil moisture sensors (for garden automation), light/UV sensors, and air quality sensors (PM2.5).

What about lightning detection? The AS3935 Franklin Lightning Sensor breakout ($10–$15) detects lightning strikes up to 40km away and estimates distance. It connects via I²C or SPI and integrates cleanly into the same Python script.

Conclusion

Building a Raspberry Pi weather station is one of the most rewarding maker projects you can tackle. You get real environmental data flowing into your smart home system, a custom 3D printed enclosure that fits your exact mounting situation, and the satisfaction of knowing exactly how your data is collected and processed — no proprietary black boxes.

Start with the BME280 for temperature, humidity, and pressure — it's the simplest sensor to wire and gives you immediate data on your Home Assistant dashboard. Add wind and rain sensors when you're ready for the full station. The modular design means you can expand incrementally without rebuilding anything.

For the enclosure, PETG or ASA printed on any entry-level 3D printer will hold up outdoors for years. Pair your weather station with other smart home devices from our ESP32 projects guide and you'll have a fully integrated home automation system with real environmental awareness.
